# Serenity BDD 5.4.2 Release Notes

**Security Updates, Consistent Environment Configuration and Smaller Releases**

This release updates a number of dependencies to address known security advisories, makes environment-specific configuration behave consistently (see [Behaviour changes](#behaviour-changes)), fixes a few small bugs, adds diagnostics for common mistakes, and continues to reduce the size of the artifacts published to Maven Central. The API additions are small: the Playwright URL and page title assertion classes are now public, and `EnvironmentVariables` has a new default method.

## Behaviour changes

### Environment-specific configuration

`environmentVariables.getProperty(..)` and `EnvironmentSpecificConfiguration` now resolve a value in the same order:

1. a value given explicitly: `-Dapp.url=...` on the command line, or set in code;
2. the chosen environment (`-Denvironment=staging`; with several, the last one wins), then the `all` block, then the `default` block of `environments { }`;
3. the plain value from `serenity.conf` or `serenity.properties`.

Three things behave differently from 5.4.1 and earlier:

- **`getProperty` finds environment-only keys.** A key defined only inside `environments { }` used to return `null` from `getProperty`, in every environment, and could only be read through `EnvironmentSpecificConfiguration`. It now returns the value for the chosen environment.
- **`-Dkey=value` overrides an environment value.** `-Dapp.url=...` did not override `environments { staging { app.url } }`; you had to write `-Denvironments.staging.app.url=...`. The short form now works, and the long form still does.
- **A key defined both at the top level and inside `environments { }`** now returns the environment value from `getProperty`, as `EnvironmentSpecificConfiguration` and Serenity's own keys (such as `webdriver.base.url`) already did. `getProperty` used to return the top-level value.

If your code or build scripts read a key that is defined in both places, check which value you expect. To keep the top-level value, remove the key from `environments { }`, or pass it explicitly with `-D`. The behaviour is described, with examples, in [Serenity System Properties and Configuration](https://serenity-bdd.github.io/docs/reference/serenity-properties).

`EnvironmentVariables` has a new default method, `isExplicitlyDefined(String)`, which returns `true` for a value given explicitly. Implementations that do not override it keep the previous behaviour.

## Bug Fixes

- **`@Narrative` on a JUnit 5 test class now reaches the report.** The story narrative was read only from `@Description`, so the text of a class-level `@Narrative` was never shown. It is now used when there is no `@Description`.
- **Playwright `Ensure.thatTheCurrentUrl()` and `Ensure.thatThePageTitle()` can be used.** They returned the package-private classes `UrlEnsure` and `PageTitleEnsure`, so every call on them (`contains`, `isEqualTo`, `matches`, `withTimeout`) failed to compile from your own code. Both are now public classes in `net.serenitybdd.screenplay.playwright.assertions` (`serenity-screenplay-playwright`).
- **A misspelt driver name suggests the right driver.** `webdriver.driver = chromee` reported "Did you mean firefox?" because the closest match was computed on upper-case names. It now ignores case and considers synonyms, so it suggests `chrome`.

## New Warnings for Common Mistakes

These log a warning and change nothing else.

- **An empty report.** When the report finds no test results, it now says so and names the usual cause: a test runner class that Maven's test plugin does not pick up, such as a Cucumber runner called `CucumberSuite` (Maven only runs classes named `*Test`, `*Tests`, `Test*` or `*TestCase`).
- **`@Managed` in a step library.** `@Managed` is only filled in on the test class, so in a step library the field stays `null` and the first use fails with a `NullPointerException` that does not mention it. Serenity now warns, once per field, and says to extend `UIInteractions` and call `getDriver()`, or to use a page object.
- **A `serenity.conf` that is ignored.** `serenity.conf` is read from the classpath (`src/test/resources`), not from the project directory. Serenity now warns, once, when it finds a `serenity.conf` in the project directory that is not on the classpath.

## Documentation and AI Assistant Support

- The documentation has a new section, [Using AI with Serenity BDD](https://serenity-bdd.github.io/docs/ai/ai_using_assistants), with a guide to [writing tests with an AI assistant](https://serenity-bdd.github.io/docs/ai/ai_writing_tests) and the pages of the exact packages, dependencies and idioms for each supported way of writing tests (Page Objects, Screenplay, Cucumber and REST, with Selenium or Playwright), configuration, upgrading, living documentation and troubleshooting by symptom. Every claim was checked against the released jars or by running it.
- [`llms.txt` and `llms-full.txt`](https://serenity-bdd.github.io/llms.txt) are generated with the documentation, for AI coding assistants.
- The repository has `AGENTS.md` files for each style, an agent skill and a test-review agent for Claude Code, in `docs/ai`. See [Using Serenity BDD with AI Coding Assistants](https://serenity-bdd.github.io/docs/ai/ai_using_assistants).
- The reference documentation now explains where Serenity reads configuration from and which source wins, how JUnit 5 test classes become requirements, why `mvn verify` builds no report when tests fail, how to pass Cucumber options under Gradle, and how to name a Cucumber runner so Maven runs it.

## Smaller Artifacts

Maven Central now applies monthly publishing limits, so Serenity's published artifacts have been trimmed. A full release is now about 65 MB, down from about 88 MB for 5.4.0, and this release reduces it further.

- **Smaller `serenity-cli` jar.** The shaded command-line jar, used by Serenity/JS, went from about 66 MB to about 37 MB. It now depends on Flexmark core instead of the full Flexmark bundle, drops an unused ICU dependency, and no longer bundles ByteBuddy and Ehcache, which only the test-execution modules use. This first shipped in 5.4.1.
- **Leaner Javadoc jars.** The generated Javadoc no longer includes web fonts (shipped in 5.4.1) or the `class-use` pages, which makes the Javadoc jars about a third smaller. The "Use" links on class pages are no longer generated; the API, search and package documentation are unchanged.
- **Unused icon assets removed.** The HTML reports use only the Bootstrap Icons stylesheet and its fonts, so the icon sprite, about 1,950 individual SVG files, and the SCSS and JSON sources have been removed from `serenity-report-resources`. That jar went from 4.0 MB to 2.7 MB.

### Upgrade note: custom report templates

If you have custom report templates that reference individual Bootstrap Icons SVG files or the `bootstrap-icons.svg` sprite directly, those files are no longer shipped. The standard Serenity reports use the icon font and are not affected.

## Build and Release

- The release workflow derives the release version from the current `SNAPSHOT` version, and the separate `deploy-cli` release profile has been removed. The CLI is now published with the rest of the modules.
- The release is built on JDK 25 (needed for the Javadoc `--no-fonts` option). Code is still compiled with `--release 17`.
- An empty `net.thucydides.core.resources` package was removed from `serenity-core`.
- `ManualScenarioChecker` in `serenity-cucumber` now uses `String.isBlank()` instead of jsoup's internal `StringUtil`.
- Modules that are only built under non-default profiles (`serenity-bitbar`, `serenity-jira-plugin`, `serenity-jira-requirements-provider`, `serenity-lambdatest`, `serenity-navigator-report`, `serenity-playwright`, `serenity-screenplay-playwright`, `serenity-selenoid` and `serenity-smoketests`) now point at the current parent version.
- Test and sample dependencies were updated for security advisories: Jetty (test scope) in `serenity-rest-assured`, and AssertJ and Jackson in `serenity-tutorials`. These do not affect published artifacts.

## Upgrade

Using the BOM (recommended):

```xml
<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>net.serenity-bdd</groupId>
            <artifactId>serenity-bom</artifactId>
            <version>5.4.2</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>
```

Or update the version directly:

```xml
<dependency>
    <groupId>net.serenity-bdd</groupId>
    <artifactId>serenity-core</artifactId>
    <version>5.4.2</version>
</dependency>
```
