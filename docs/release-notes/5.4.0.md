# Serenity BDD 5.4.0 Release Notes

**Cucumber 8 Upgrade and Dependency Updates**

This release upgrades Serenity's Cucumber integration to Cucumber 8.0.4 and brings Selenium, JUnit 5 and a number of security-sensitive dependencies up to date.

## Upgrade Notes

### Cucumber 8.x

`serenity-cucumber` now builds against Cucumber 8.0.4 (previously 7.34.x). Because this is a major upgrade of a library that is exposed to your test code, this release is a minor version bump rather than a patch release. If your project has custom Cucumber plugins, formatters or other code that uses Cucumber APIs directly, check it against the [Cucumber 8 release notes](https://github.com/cucumber/cucumber-jvm/blob/main/CHANGELOG.md) before upgrading. The Serenity test suites in this repository were updated for Cucumber 8 as part of this release.

## Dependency Updates

| Dependency | Previous | Now |

| Cucumber | 7.34.2 | 8.0.4 |
| Selenium | 4.46.0 | 4.51.0 |
| HtmlUnit driver | 4.45.0 | 4.51.0 |
| JUnit 5 | 6.0.3 | 6.1.3 |
| Appium Java client | 10.0.0 | 10.1.1 |

Several of these (Jackson, Thymeleaf, Spring, Netty) address known CVEs.

### Selenium 4.51

The Firefox profile helpers removed from Selenium (`setAssumeUntrustedCertificateIssuer`, `setAcceptUntrustedCertificates` and `setAlwaysLoadNoFocusLib`) are no longer used. Serenity now sets the `webdriver_accept_untrusted_certs` preference instead, so the `refuse.untrusted.certificates` setting continues to control the behaviour.

## Bug Fixes

### `RequirementCache` Thread Safety (#3753)

`RequirementCache` is now safe to read and update from the report generation threads, so reports can be generated concurrently without corrupting the cache.

### Functional Coverage on the Single-Page Summary Report (#3751)

The functional coverage section is displayed again on the single-page summary report.

## Build and Release

- The Maven Central release workflow now accepts an optional `release_version` input and can publish either the full module set (`deploy`) or the independent CLI (`deploy-cli`).
- The release workflow pins Maven to 3.9.14. Maven 3.10.0 causes the Central publishing plugin to include `maven-metadata-local.xml` files in the bundle, which Central rejects.
- Duplicate `assertj-core` dependency declarations in `serenity-stats`, `serenity-screenplay-webdriver` and `serenity-json-summary-report` were removed; they prevented `release:prepare` from running.

## Tests

The Playwright module's tests (and `JQueryInteractionTests` in `serenity-screenplay-webdriver`) now run against local HTML fixtures served from the test classpath instead of `the-internet.herokuapp.com`, `example.com` and `jqueryui.com`, so they no longer depend on external sites.

## Upgrade

Using the BOM (recommended):

```xml
<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>net.serenity-bdd</groupId>
            <artifactId>serenity-bom</artifactId>
            <version>5.4.0</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>
```

Or update the version directly:

```xml
<dependency>
    <groupId>net.serenity-bdd</groupId>
    <artifactId>serenity-core</artifactId>
    <version>5.4.0</version>
</dependency>
```

Version 5.3.12 and 5.3.13 were not published to Maven Central; upgrade directly from 5.3.11.
