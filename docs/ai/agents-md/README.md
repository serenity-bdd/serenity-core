# AGENTS.md templates for Serenity projects

`AGENTS.md` is the open convention for telling AI coding tools how a project works. These templates record **which Serenity style a project uses**, so an assistant stays in it instead of mixing styles or guessing packages.

There is one variant per style, in `variants/`. Copy the one that matches the project to its root as `AGENTS.md`:

| File | Approach | Driver |
|---|---|---|
| `AGENTS.po-selenium.md` | Page Objects + step library | Selenium |
| `AGENTS.po-playwright.md` | Page Objects + step library | Playwright |
| `AGENTS.sp-selenium.md` | Screenplay | Selenium |
| `AGENTS.sp-playwright.md` | Screenplay | Playwright |
| `AGENTS.sp-rest.md` | Screenplay | REST |
| `AGENTS.cuke-sp.md` | Cucumber with Screenplay | Selenium |

All use JUnit 5 (Cucumber on the JUnit Platform). None is preferred over another; the variant records the project's choice.

Each file says: the fixed style, driver and runner; what to avoid; the structure; the verified imports and common mistakes for that style; how to compile, run and find the report; a few working rules; and links to the full docs and `llms.txt`.

## Using it

1. Copy the matching variant to `AGENTS.md` in the project root and commit it.
2. Adjust the "Structure" section to the project's package layout, and add any project rules (naming, test data, environments).
3. Tools that read `AGENTS.md` pick it up directly. Claude Code reads `CLAUDE.md`: copy the file to `CLAUDE.md`, or put an import line in `CLAUDE.md` (not tested here).

For a new project, ask the team which style it wants first. The templates are not a default.

## Keeping it correct

The files are generated by `build.py` (edit the data there, then run `python3 build.py`). The idiom lines come from `../skill/serenity-bdd/references/`, verified against Serenity 5.4.1 (Playwright modules 5.3.11). Update them when a release changes a package or a recommendation. The starter projects (roadmap WS6) should ship the matching variant.
